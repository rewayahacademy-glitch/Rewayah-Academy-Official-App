## 1. Contraintes de routage qui s'imposent à toutes les lignes (CODE)

| Id | Contrainte | Preuve |
|---|---|---|
| R1 | Tout chemin d'un tuteur connecté doit rester sous `/tuteur` (garde G-PRE), sinon redirection silencieuse vers `/tuteur`. Aucune route `/appareils/...` ni `/appareil/...` à la racine. | `redirection.dart:114-115`, `routes.dart:359-366` |
| R2 | `prefixePour(guardian)` renvoie `Routes.tuteurAccueil`. Changer la valeur de cette constante réduit le préfixe de garde de tout `/tuteur/*`. On garde `/tuteur` comme racine (ou on découple d'abord `prefixePour`). | `routes.dart:65, 359-366` |
| R3 | Un écran vu sans session (appareil élève, récupération d'accès) vit sous le sous-arbre public `/connexion/...`, ou exige d'amender G-PUB. | `redirection.dart:39-49` |
| R4 | L'admission suit la porte d'accès : avant profil seul `/inscription/*` passe ; dossier en attente seul `/attente/*` ; compte actif `/tuteur/*`. Un préfixe `/onboarding` serait redirigé dans les trois cas. | `redirection.dart:55-68, 81-87`, `session_state.dart:133-172` |
| R5 | Un segment dynamique (`:eleveId`, `:classeId`, `:seanceId`) se déclare après ses frères statiques (`ajouter`, `appareils`, `appairer`, `catalogue`, `observations`). | go_router, ordre de déclaration |
| R6 | Pour garder la barre de navigation et l'état, une sous-page vit dans la `StatefulShellBranch` de sa destination. Aujourd'hui foyer, ajout, appairage, parcours, `/tc/*` sont hors coquille (retour Android = sortie d'application). | `app_router.dart:236-298` |
| R7 | Aucun secret dans une URL : code d'appairage, PIN, jeton appareil, billet de salle restent hors URL. Un paramètre `retour` est un chemin interne validé (jamais `/salle`, `/tc/classe`, `/agent`, ni URL absolue). | `C01` §8, `billet_salle.dart` |
