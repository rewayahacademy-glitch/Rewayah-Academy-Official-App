# Leçons de la nuit du 16 au 17/10/2026

Une ligne par erreur : qui, quoi, pourquoi, la règle qui l'évite.

- Auditeur (16/10) : a écrit « pas de site public » sans lister les branches distantes ; le site vivait sur `codex/site-public-local-2026-10-13`. Règle : `git ls-remote --heads origin` et une recherche au tableau Suivi avant d'écrire « n'existe pas ».
- Prompt de l'orchestrateur (16/10) : supposait le garde-fou `garde.py` actif ; une session cloud qui démarre sur une branche sans `.claude/` ne le charge pas. Règle : vérifier `ls .claude/` au démarrage ; si absent, appliquer les zones à la main dans chaque consigne d'agent.
- Prompt de l'orchestrateur (16/10) : supposait Docker démarré ; dans le conteneur cloud, le démon est installé mais arrêté. Règle : `nohup dockerd &` puis `docker info` au cycle 0.
- Fiche L1-09 (auditeur) : demandait que la liste blanche échoue sur l'ancien stub ; une liste blanche ne voit que l'excédent. Règle : un critère « échoue avant » se vérifie en pensant au sens du contrôle (excédent ou manque) avant de l'écrire.
- Fiche L1-09 (auditeur) : signatures écrites avec le préfixe `public.` ; `regprocedure` l'omet quand `public` est dans le `search_path`. Règle : copier la sortie de la requête, jamais une signature tapée.
- Agent L1-09 : un second `stub_auth.sql` sur le même conteneur échoue (rôles globaux au cluster). Règle : un conteneur neuf par rejeu complet du stub ; `create database ... template` seulement après le stub.
- Fiche L1-09 (auditeur) : chemin de test faux (`bibliotheque-upload/` au lieu de `_shared/r2/`). Règle : chaque chemin d'une fiche se vérifie par `ls` avant d'être écrit.
- Fiche L1-09 (auditeur) : proposait `needs: [migrations, flutter]` entre deux fichiers de workflow ; `needs` ne traverse pas les fichiers. Règle : lire les deux workflows avant de proposer une dépendance de jobs.
- Fiche L1-01 (auditeur) : n'avait pas vu que les appelants de log_sensitive_access sont des triggers INVOKER ; un revoke casse l'administration. Règle : avant un revoke, lister les appelants par pg_proc.prosecdef, pas par grep.
- Agent L1-01 : un refus qui échoue sur une clé étrangère ne prouve pas le refus. Règle : un scénario de refus vérifie SQLSTATE 42501 exactement.
- Orchestrateur : scratchpad partagé entre agents, un script d'un lot a écrasé celui d'un autre. Règle : un sous-dossier de scratchpad par lot, nommé dans la consigne.
- Fiche L1-07 (auditeur) : une colonne ajoutée à une garde casse les fixtures temporaires de b18 qui copient profiles. Règle : chercher profile_guard_fixture avant d'étendre la garde.
- Fiche L1-06 (auditeur) : « immuable » sans lire les triggers de x2_17 qui posent la confirmation prestataire. Règle : avant de figer une table, lister ses triggers AFTER UPDATE et les scénarios qui la modifient.
- Agent L1-05 : rapport avec un compte de migrations faux (21 au lieu de 200). Règle : l'orchestrateur rejoue lui-même tout chiffre de rapport qui ne correspond pas au total attendu, avant d'accepter.
- Agents L1-01, L1-04, L1-06 : nom de modèle dans le co-auteur du commit, contre la règle du dépôt. Règle : la consigne d'agent donne la ligne exacte et interdit tout nom de modèle ; l'orchestrateur relit les messages avant de pousser.
- Fiches et message de démarrage (auditeur, garde-fou) : disent que garde.py refuse supabase/, alors que sa liste de zones ne le contient plus. Règle : lire ZONES_INTERDITES dans garde.py ou tester un chemin avant d'écrire qu'une zone est fermée.
- Fiche L2-04 (auditeur) : cite port_suivi.dart et un port planning qui n'existent pas, et n'autorise pas les faux qui implémentent les ports. Règle : une fiche qui change une signature liste tous les implements (grep) dans ses fichiers autorisés.
- Prompt de l'orchestrateur : supposait la préversion Vercel joignable ; le proxy du conteneur la refuse (403). Règle : tester curl sur la préversion au cycle 0 ; sinon construire et servir le web en local.
- Fiche L1-08 (auditeur) : n'avait pas vu que adm04 affirme la lecture du journal par le contrôleur, ni que trois policies servent les comptes pending_kyc qu'app_account_valid() refuse. Règle : avant d'envelopper une policy, grep les scénarios qui l'exercent et lister les statuts de compte qu'elle sert.
- Fiche L2-03 (auditeur) : cite depotCahiersProvider, DepotCahiers.rejouer et enLigneProvider, qui n'existent pas (réels : soumissionCahierProvider, SoumissionCahier.rejouer, horsLigneProvider). Règle : chaque symbole d'une fiche se vérifie par grep avant d'être écrit. Et : une clé i18n nouvelle exige une ligne dans tool/libelles_sources.json, à mettre dans les fichiers autorisés.
- Agent L2-04 : un provider d'écran qui lit sessionProvider casse tout test sans override (sourceSessionProvider touche Supabase.instance). Règle : un identifiant de session lu par un provider d'écran passe par une lecture qui rend null hors session.
- Fiche L2-02 (auditeur) : parle de PortDossier et de detail_dossier.dart ; le port réel est ServiceValidation et l'état d'aperçu vit dans visionneuse_piece.dart. Règle : la fiche nomme les fichiers après un grep de l'appelant réel. Les .g.dart de slang sont désynchronisés sur la base : à régénérer dans un lot dédié.
- Orchestrateur : plusieurs flutter test complets en parallèle sur la même machine se coupent (répertoires /tmp/flutter_tools partagés). Règle : un seul flutter test complet à la fois, sur la branche d'intégration ; les agents de lot ne lancent que leurs tests ciblés.
