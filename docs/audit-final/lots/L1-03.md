# L1-03 - Le cahier brut de l'enseignant n'est lu que par son auteur, l'administration et le contrôleur en mission

Vague 1 (sécurité). Dépend de L1-09. Indépendant de L1-02 et L1-04.

## 1. But et pourquoi (P0-2 partie cahier, P2-1, rapport section 4.1 et 4.3 ; doc maître 15.2 : la famille lit un résumé, jamais le cahier brut)

Sur STAGING, `lesson_reports_reader` autorise `session_in_household(session_id, app_household_id())` et `session_has_participant(session_id, auth.uid())` : un enfant lit les notes internes de son enseignant (`lesson_reports`) et les constats de prononciation (`makharij_findings`) de toute séance de son foyer. La même policy donne au contrôleur (`app_role() = 'controller'`) tous les cahiers de toutes les séances, hors mission. La famille doit lire la projection (`seance_resumes` ou la vue de résumé tuteur raccordée par `PED-APRES-BACK`), pas la source.

## 2. Critère de réussite

C'est fini quand :

1. une migration horodatée réécrit `lesson_reports_reader` et `makharij_findings_read` : auteur (`author_profile_id = auth.uid()` et rôle `teacher`), administration (`admin` avec `app_account_valid()`), contrôleur seulement pour une séance de ses missions ;
2. le scénario `supabase/tests/scenarios_af_l1_03_cahier_brut.sql` prouve qu'un jeton `student` du foyer lit zéro ligne de `lesson_reports` et `makharij_findings`, qu'un `guardian` du foyer lit zéro ligne, qu'un `controller` sans mission sur la séance lit zéro ligne et qu'avec une mission il lit la ligne, que l'auteur lit la sienne ;
3. l'écran du tuteur qui montre le résumé de séance (`lib/features/suivi_foyer/detail_seance_page.dart`) ne lit pas `lesson_reports` directement (vérifié par `grep`) ; s'il le fait, c'est noté en section 8 pour la vague 2.

## 5. Étapes

1. Déterminer l'expression « contrôleur en mission sur cette séance » à partir de `rejoindre_observation` et de la table des missions. L'écrire sous la forme d'une fonction privée si elle n'existe pas déjà :

```sql
create or replace function private.af_controleur_en_mission(p_session_id uuid)
returns boolean language sql stable security definer set search_path = ''
as $$
  select exists (
    select 1 from public.<table_missions> m
     where m.<colonne_session> = p_session_id
       and m.<colonne_controleur> = auth.uid()
       and m.<colonne_etat> in (<états actifs lus dans la table>)
  );
$$;
revoke all on function private.af_controleur_en_mission(uuid) from public, anon, authenticated, agent_ro;
```

   Si une fonction équivalente existe déjà dans `private` (chercher `grep -n "mission" supabase/migrations/20261011*.sql`), la réutiliser et ne rien créer.
2. Écrire la migration :

```sql
-- Audit final 16/10/2026, lot L1-03 (P0-2 cahier, P2-1). Le cahier brut est la
-- note de travail de l'enseignant. La famille lit la projection, pas la source.
begin;

-- (étape 1 si nécessaire)

alter policy lesson_reports_reader on public.lesson_reports
  using (
    public.app_account_valid() and deleted_at is null
    and (
      (public.app_role() = 'teacher' and author_profile_id = auth.uid())
      or public.app_role() = 'admin'
      or (public.app_role() = 'controller' and private.af_controleur_en_mission(session_id))
    )
  );

alter policy makharij_findings_read on public.makharij_findings
  using (
    public.app_account_valid() and deleted_at is null
    and exists (
      select 1 from public.lesson_reports lr
       where lr.id = makharij_findings.lesson_report_id and lr.deleted_at is null
         and (
           (public.app_role() = 'teacher' and lr.author_profile_id = auth.uid())
           or public.app_role() = 'admin'
           or (public.app_role() = 'controller' and private.af_controleur_en_mission(lr.session_id))
         )
    )
  );

do $postflight$
declare v_q text;
begin
  select qual into v_q from pg_policies where schemaname = 'public' and policyname = 'lesson_reports_reader';
  if v_q like '%session_in_household%' or v_q like '%session_has_participant%' then
    raise exception 'L1-03 postflight: la famille lit encore le cahier brut';
  end if;
end $postflight$;

commit;
```

   La policy `lesson_reports_reader` est déclarée `to agent_ro, authenticated` : `alter policy` conserve cette liste. Vérifier après rejeu que `agent_ro` n'obtient rien de plus (son rôle applicatif n'est ni `teacher`, ni `admin`, ni `controller`).
3. Écrire le scénario avec cinq jetons (auteur `teacher`, `admin`, `controller` sans mission, `controller` avec mission, `student` et `guardian` du foyer de la séance). Préparer sous `postgres` : une séance, un participant élève, un `lesson_reports` écrit par l'auteur, un `makharij_findings` rattaché, une mission pour un contrôleur sur cette séance. Pour chaque jeton, `select count(*) from public.lesson_reports` et `from public.makharij_findings`, attendu 1 pour l'auteur, l'admin et le contrôleur en mission ; 0 pour les autres. Modèle de forme : fiche L1-02 étape 3.
4. Rejouer tout sur PostgreSQL 17 neuf (stub L1-09, migrations, 15 scénarios CI, nouveau scénario). Le nouveau scénario doit échouer sur une base sans la migration.
5. `grep -rn "lesson_reports\|makharij" lib/core lib/features --include=*.dart | grep -v "^lib/features/enseignant\|^lib/features/cahier\|^lib/features/controleur\|^lib/features/admin"`. Résultat attendu : aucune lecture depuis un écran de famille. Sinon section 8.

## 7. Pièges connus

- `lesson_reports_teacher_write` est déclarée pour le rôle `{public}` (P3-4) : hors lot, ne pas corriger ici.
- Le contrôleur lit aussi `audit_logs` en entier (`audit_logs_read`, P2-1) : traité par L1-08, pas ici.
- Un résumé familial inexistant côté serveur rendrait l'écran du tuteur vide après ce lot : vérifier à l'étape 5. Le rapport (matrice E-07, PED-APRES-BACK) dit que la projection par séance est encore à faire : si le tuteur lit aujourd'hui `lesson_reports`, ce lot casse l'écran et il faut le dire (section 8), pas reculer sur la sécurité.
- `security definer` sur la fonction privée est nécessaire parce que `authenticated` n'a pas de droit de lecture direct sur la table des missions ; `search_path = ''` obligatoire.
