# L1-11 - Fermer l'inscription d'un enseignant sans code d'invitation - conditionnel à l'arbitrage A-07

Vague 1, lot conditionnel : ne commence qu'après la décision écrite du directeur sur A-07 (rapport section 7).

## 1. But et pourquoi (matrice E-01 ; doc maître 9.1 : un enseignant entre par invitation)

`creer_profil_inscription(p_role text, ...)` accepte `'teacher'` sans code d'invitation valide, alors qu'une porte par invitation existe (`20261016102200_raccordement_invitation_consommee.sql`, écrans `lib/features/admin_invitations/`). Deux portes coexistent ; n'importe qui ouvre un dossier enseignant.

## 2. Critère de réussite

C'est fini quand :

1. une migration horodatée redéfinit `creer_profil_inscription` : si `p_role = 'teacher'`, lever `'inscription enseignant sur invitation seulement'` (`check_violation`), sauf si la fonction est appelée depuis le chemin d'invitation (lire comment `20261016102200` consomme l'invitation : si l'invitation est consommée dans la même RPC, ajouter un paramètre `p_code_invitation text default null` et exiger qu'il soit valide ; sinon, laisser la RPC d'invitation seule créer l'enseignant) ;
2. le scénario `supabase/tests/scenarios_af_l1_11_inscription_enseignant_invitation.sql` prouve : `creer_profil_inscription('teacher', ...)` sans code est refusé ; avec un code valide (ou par la RPC d'invitation) réussit ; `creer_profil_inscription('guardian', ...)` et `('student', ...)` inchangés ;
3. l'écran d'inscription (`lib/features/inscription/`) ne propose plus « Enseignant » sans code : lot frontal séparé, libellés FR « Vous êtes enseignant ? L'académie vous invite par courriel. » / AR « هل أنت معلّم؟ تدعوك الأكاديمية عبر البريد الإلكتروني. » ; aucun bouton grisé (K-59) : un lien « J'ai un code d'invitation » ouvre le champ.
