# L2-02 - L'aperçu d'une pièce d'identité passe par la porte tracée `piece-identite-acces`

Vague 2 (raccordements). Dépend de L1-V. Indépendant des autres lots.

## 1. But et pourquoi (P2-4, rapport section 4.3 ; matrice D-03 ; `02_ARCHITECTURE_ET_SECURITE.md` : accès KYC journalisé)

`lib/core/dossier/service_validation.dart:221-223` demande l'aperçu par `storage.from('kyc').createSignedUrl(cleObjet, ...)`. Or la policy Storage `kyc_client_read_block` (`0088`) ferme le seau au client : « Voir la pièce » échoue pour l'administration. La porte prévue existe : fonction Edge `piece-identite-acces` (vérifie le compte, journalise `log_sensitive_access`, résout la clé côté serveur, refuse tout `object_key` venu du client, signe une lecture courte). Le client doit l'appeler.

## 2. Critère de réussite

C'est fini quand :

1. `apercu(...)` dans `ServiceDossierSupabase` appelle `_client.functions.invoke('piece-identite-acces', body: {<le champ attendu>})` et rend l'URL signée du corps de réponse ;
2. le port `PortDossier` (ou le nom réel du port de `lib/core/dossier/port_*.dart`) prend un identifiant de DOCUMENT, pas une clé d'objet : si l'écran passe encore `cleObjet`, changer la signature en `apercu(String documentId)` et adapter l'appelant unique dans `lib/features/admin_dossiers/detail_dossier.dart` ;
3. un test Dart `test/core/dossier/service_validation_apercu_test.dart` prouve, avec un faux client Supabase (modèle : les tests existants de `test/core/dossier/`), que l'appel part vers la fonction Edge avec le bon corps et qu'une réponse `403` devient l'erreur typée que l'écran sait montrer (état erreur avec action « Réessayer » et explication « Votre genre ne permet pas de voir cette pièce » si le code retour le dit : lire la fonction Edge pour les codes) ;
4. aucune occurrence de `createSignedUrl` ne reste sur le seau `kyc` (`grep -rn "seauKyc\|'kyc'" lib/core`).

## 5. Étapes

1. Lire la fonction Edge : noter le nom du champ du corps (probablement `document_id`), la clé de la réponse (`url`), les codes (`400` clé interdite, `401`/`403` refus, `404` introuvable) et la durée de validité.
2. Remplacer `apercu` :

```dart
  @override
  Future<String> apercu(String documentId) async {
    final FunctionResponse reponse = await _client.functions.invoke(
      'piece-identite-acces',
      body: <String, dynamic>{'document_id': documentId},
    );
    final Map<String, dynamic> corps = reponse.data as Map<String, dynamic>;
    return corps['url'] as String;
  }
```

   Adapter les noms à ce que l'étape 1 a lu. Traduire une `FunctionException` (statut 403) en l'exception typée déjà utilisée par le service pour le genre (`GenreLecteurInconnu` existe ; créer `ApercuRefuse` si aucune ne convient, dans le même fichier que les autres exceptions du port).
3. Si le port expose `apercu(String cleObjet)`, renommer le paramètre et faire passer `dossier.id` depuis `detail_dossier.dart`. Mettre à jour le double de démonstration (il rend une URL de placeholder, inchangé sinon).
4. Dans `detail_dossier.dart`, vérifier que l'échec d'aperçu passe par un état erreur avec action (K-59). S'il affiche déjà `EtatErreur` avec « Réessayer », ajouter seulement la phrase de cause pour le 403 : FR « Cette pièce n'est pas visible avec votre compte. » / AR « هذه الوثيقة غير مرئية بحسابك. » (clé `dossiers.detail.apercuRefuse`).
5. Test : `test/core/dossier/service_validation_apercu_test.dart` avec le faux client des tests existants ; deux cas : succès (URL rendue, corps envoyé = `{document_id}`), 403 (exception typée).
6. `dart run slang` (si une clé i18n a été ajoutée), `dart run build_runner build --delete-conflicting-outputs`, `dart analyze --fatal-infos`, `flutter test test/core/dossier test/features/admin_dossiers`, puis `flutter test`.

## 7. Pièges connus

- La fonction Edge refuse explicitement un `object_key` dans le corps (ligne 76) : envoyer l'identifiant du document, jamais la clé.
- `functions.invoke` lève `FunctionException` sur un statut non 2xx dans les versions récentes de `supabase_flutter` ; dans d'autres, le statut est dans `reponse.status`. Lire la version dans `pubspec.lock` et la documentation du connecteur, pas la mémoire.
- Le genre du lecteur commande la visibilité (`0088`) : un 403 n'est pas une panne, c'est une règle. Le message doit le dire sans « erreur ».
- Ne pas toucher `decider(...)` dans le même fichier (L1-05 agit côté serveur ; l'erreur « dossier déjà décidé » arrive comme `PostgrestException`, et l'écran la montre déjà si son état d'erreur est générique).

## 8. Quand s'arrêter et demander

- La fonction Edge attend un corps différent de `document_id` et le port n'a pas cet identifiant sous la main : s'arrêter, nommer le champ.
- `detail_dossier.dart` n'a aucun état d'erreur pour l'aperçu : s'arrêter, c'est un écart DESIGN-GOV à chiffrer à part.
