# L2-03 - La file des cahiers hors ligne se rejoue vraiment

Vague 2 (raccordements). Dépend de L1-V. Indépendant des autres lots.

## 1. But et pourquoi (matrice E-08, rapport section 5.2 ; doc maître 15.1 : le cahier écrit hors ligne part au retour du réseau ; `06` ligne Mode hors ligne)

`DepotCahiers.rejouer()` (`lib/core/enseignant/depot_cahiers.dart:145`) vide la file des cahiers en attente. Il n'est appelé que par deux tests. Un cahier écrit hors ligne reste donc en file jusqu'au prochain `envoyer` d'un autre cahier. La promesse « reprise de file d'attente » n'est pas tenue.

## 2. Critère de réussite

C'est fini quand :

1. `rejouer()` est appelé à deux moments : à l'ouverture de l'espace enseignant (première construction de la coquille `lib/features/journee/` ou de la coquille enseignant, une fois par session) et au retour du réseau (`lib/core/reseau/service_reseau.dart` expose l'état ; brancher sur son passage hors ligne vers en ligne) ;
2. quand `rejouer()` rend `n > 0`, l'enseignant voit une confirmation discrète : FR « {n} cahier envoyé » / « {n} cahiers envoyés » (pluriel slang), AR « تم إرسال {n} دفتر » / « تم إرسال {n} دفاتر » ; quand il rend 0, rien ;
3. un test widget `test/features/journee/rejouer_cahiers_test.dart` prouve : avec un faux dépôt dont la file contient 2 cahiers, l'ouverture de la Journée appelle `rejouer` une fois et affiche « 2 cahiers envoyés » ; avec une file vide, rien ; une bascule hors ligne vers en ligne du faux service réseau appelle `rejouer` à nouveau ;
4. l'appel ne bloque jamais l'affichage (lancé après le premier rendu, erreurs avalées et journalisées, jamais de rouge sur l'écran : le cahier reste en file, c'est l'état normal).

## 5. Étapes

1. Repérer le provider du dépôt et le provider d'état réseau (section 3). Noter leurs noms exacts.
2. Dans la page Journée (ou la coquille enseignant), ajouter un `ConsumerStatefulWidget` minimal ou un `ref.listen` dans `build` :

```dart
    ref.listen<bool>(enLigneProvider, (bool? avant, bool apres) {
      if (avant == false && apres) _rejouerCahiers();
    });
```

   et dans `initState` (via `WidgetsBinding.instance.addPostFrameCallback`) un premier `_rejouerCahiers()`.
3. `_rejouerCahiers` :

```dart
  Future<void> _rejouerCahiers() async {
    try {
      final int n = await ref.read(depotCahiersProvider).rejouer();
      if (n > 0 && mounted) {
        afficherConfirmation(context, t.journee.cahiersEnvoyes(n: n));
      }
    } catch (_) {
      // La file garde le cahier : ce n'est pas une erreur pour l'enseignant.
    }
  }
```

   Utiliser le composant de confirmation du dépôt (section 3), pas un `SnackBar` brut.
4. i18n : clé `journee.cahiersEnvoyes` avec pluriel slang (`one`, `other`) en FR et AR (l'arabe a `one`, `two`, `few`, `many`, `other` : fournir au moins `one`, `two`, `other` : « تم إرسال دفتر واحد », « تم إرسال دفترين », « تم إرسال {n} دفاتر »). Ajouter le commentaire de source demandé par `verifier_revue` (lire la convention dans `tool/verifier_revue.dart`).
5. Test widget (critère 3) avec un faux `DepotCahiers` (classe de test qui compte les appels à `rejouer` et rend 2 puis 0) et un faux provider réseau (`StateProvider<bool>` surchargé).
6. `dart run slang`, `dart run build_runner build --delete-conflicting-outputs`, `dart analyze --fatal-infos`, `flutter test test/features/journee test/core/enseignant`, `flutter test`.
7. Capture 390 clair de la Journée avec la confirmation visible (test de capture ou préversion locale) : `docs/audit-final/captures/lots/L2-03_journee_390_light.png`.

## 6. Vérifications

- Les cinq commandes du dépôt vertes ; `verifier_jetons` sans augmentation ; `verifier_revue` : la nouvelle clé porte sa source.
- Le test prouve « une fois à l'ouverture » : pas deux appels si la page se reconstruit.

## 7. Pièges connus

- `ref.listen` dans `build` d'un `ConsumerWidget` se réabonne à chaque build : c'est voulu par Riverpod 3, mais le rappel ne doit pas dépendre d'un état local. Préférer `ConsumerStatefulWidget` et `ref.listenManual` dans `initState` si la page est déjà un `StatefulWidget`.
- `rejouer()` envoie par le service réel : en test, le faux dépôt ne doit pas toucher au réseau.
- Un cahier qui échoue à l'envoi (serveur 4xx) reste en file : c'est le comportement de `_file.vider` (lire `lib/core/enseignant/file_*.dart`). Ne pas inventer de compteur d'échecs ici.
- Les écrans d'autres rôles ne doivent pas rejouer : seule la coquille enseignant.

## 8. Quand s'arrêter et demander

- Aucun provider d'état réseau n'existe (seulement un service sans flux) : s'arrêter, proposer d'en exposer un dans `lib/core/reseau/` (hors lot).
- La Journée n'est pas la première page de l'enseignant (redirection vers `bienvenue_enseignant` ou autre) : brancher dans la coquille commune et le dire.
