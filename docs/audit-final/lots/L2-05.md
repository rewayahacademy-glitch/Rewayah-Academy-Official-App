# L2-05 - Écran d'administration des offres vitrine : créer, publier, retirer

Vague 2 (raccordements). Dépend de L1-V. Deux parties : port et écran (Claude), adaptateur (Codex). Le lot le plus gros de la vague.

## 1. But et pourquoi (matrice A-01, A-02 ; `DECISION-OFFRES-GROUPES-2026-10-09.md` section 1 : seule l'administration publie ; la vitrine se compose d'offres sans enseignant)

Le serveur a tout : `creer_offre_horaire(p_type_public text, p_langue_code text, p_fuseau_iana text, p_jours smallint[], p_heure_locale smallint, p_duree_minutes smallint)`, `publier_offre_horaire(p_offre_id uuid)`, `retirer_offre_horaire(p_offre_id uuid, p_motif text)` (`0043_offres_horaires_et_intentions.sql:1050-1160`), table `offres_horaires` avec policy `offres_horaires_vitrine`. Aucun écran ne les appelle : `grep -rn "creer_offre_horaire\|publier_offre_horaire" lib/` rend zéro ligne. La vitrine réelle est donc vide ; une famille ne peut pas choisir d'horaire sur STAGING ; la chaîne demande, regroupement, « Créer la classe » (qui existe) ne démarre jamais.

## 2. Critère de réussite

C'est fini quand :

1. une route `/admin/operations/offres` existe, atteinte depuis la section Opérations de la coquille administrateur (à côté de « Classes à ouvrir » et « Classes »), gardée par la capacité d'administration déjà utilisée par ces pages (jamais par le rôle) ;
2. l'écran liste les offres (brouillon, publiée, retirée), avec un seul bouton plein « Nouvelle offre » / AR « عرض جديد » ; une offre se crée dans une tâche focalisée (`PageParcours`) en une étape : type de public (enfant, adolescent, adulte, tel que l'énumération serveur le définit : lire `0043`), langue du cours, fuseau IANA (liste courte, défaut celui du poste), jours (cases), heure locale (sélecteur à pas de 30 min ou l'unité acceptée par le serveur), durée (valeurs de `app_config` ou 45 et 60) ;
3. une offre en brouillon se publie (« Publier » / « نشر ») ; une offre publiée se retire avec motif obligatoire (« Retirer » / « إزالة », motif : « Motif du retrait » / « سبب الإزالة ») ;
4. les cinq états : loading (squelette de liste), content, empty (« Aucune offre pour l'instant. Créez la première pour ouvrir la vitrine aux familles. » / « لا توجد عروض حتى الآن. أنشئ العرض الأول لفتح الواجهة للعائلات. »), error (avec « Réessayer »), offline ;
5. le port `lib/core/offres/port_offres_admin.dart` déclare `lister()`, `creer(...)`, `publier(id)`, `retirer(id, motif)` avec un double de démonstration ; l'adaptateur `lib/core/offres/offres_admin_supabase.dart` appelle les trois RPC et lit `offres_horaires` ; il est branché dans `lib/main.dart` par un `overrideWith` à côté des 49 existants ;
6. tests widget 390 et 1440, clair, arabe (miroir), texte x2 à 320 : liste avec 3 offres, état vide, création avec validation (aucun jour choisi : message « Choisissez au moins un jour » / « اختر يومًا واحدًا على الأقل »), retrait sans motif refusé ;
7. `verifier_revue` : zéro `plein-multiple` sur le nouvel écran (contrat B règle 4) ; `verifier_jetons` sans augmentation.

## 7. Pièges connus

- `p_jours smallint[]` : envoyer une liste d'entiers ; `supabase_flutter` sérialise `List<int>` en tableau JSON, PostgREST le convertit. Vérifier la convention de numérotation des jours dans `0043` (1 à 7 ou 0 à 6).
- `p_heure_locale smallint` : lire si c'est une heure entière (0 à 23) ou des minutes depuis minuit ; `DECISION-CLASSES-SIMULTANEES` parle de « clé horaire » : s'y conformer.
- Une offre publiée ne se modifie pas (immuabilité des offres, `0043`) : l'écran ne propose pas « Modifier », seulement « Retirer » puis « Nouvelle offre ».
- Aucune liste d'enseignants sur cet écran : la vitrine est sans enseignant (décision du 09/10). Ne pas ajouter de champ enseignant.
- Fuseau : l'offre porte le fuseau de l'académie ou celui choisi ; la famille voit l'heure locale convertie côté vitrine (déjà fait dans `parcours_offres`).
