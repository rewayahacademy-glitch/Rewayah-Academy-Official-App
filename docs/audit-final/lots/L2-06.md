# L2-06 - Observation du tuteur ouverte en staging (drapeau) - après A-09 et après la vague 1

Vague 2 (raccordements). Dépend de L1-V et de la décision A-09 (recommandation : ouvrir). Petit lot.

## 1. But et pourquoi (matrice T-19 ; doc maître 11.4 : le tuteur observe 2 fois 120 s par mois ; rapport section 5.2)

Le serveur est prêt (`rejoindre_observation`, quotas `observation.*` dans `app_config`, jeton borné `guardian_observer`). L'écran existe (`lib/features/tc_observation_ui/`). Il est fermé par `Env.observationTuteurReelleSelon(demandee, environnement)` (`lib/core/config/env.dart:94-97`) qui ne rend vrai qu'en `developpement`, par liste d'autorisation voulue (commentaire lignes 86 à 93). La préversion est compilée `ENVIRONNEMENT=staging` : personne ne peut recetter l'observation réelle sur STAGING.

## 2. Critère de réussite

C'est fini quand :

1. `observationTuteurReelleSelon` rend vrai pour `developpement` et `staging` quand `demandee` est vrai, faux pour tout le reste (`production`, chaîne vide, casse différente) ;
2. le test existant de la règle (`test/core/config/env_test.dart` ou le fichier qui teste `observationTuteurReelleSelon` : `grep -rln "observationTuteurReelleSelon" test/`) est étendu : `staging` vrai, `Staging` faux, `production` faux ;
3. le commentaire de `env.dart` est mis à jour pour dire pourquoi `staging` entre dans la liste (décision A-09, après la vague 1 de sécurité) ;
4. rien d'autre ne change : la compilation de la préversion doit toujours passer `OBSERVATION_TUTEUR_REELLE=true` pour que le drapeau s'ouvre (c'est `flutter-deploy.yml`, hors de portée ; le dire dans le commit : sans ce `--dart-define`, le lot ne change rien de visible).
