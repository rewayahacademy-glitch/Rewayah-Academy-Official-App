# L2-09 - Policies Storage : supports par version autorisée, avatars d'élève lisibles par l'enseignant de la Classe, photos d'enseignant réservées aux enseignants

Vague 2 (raccordements). Dépend de L1-V. Indépendant des autres lots.

## 1. But et pourquoi (P2-3, P3-3, rapport sections 4.3 et 4.4 ; matrice S-08, T-10)

Trois policies du schéma `storage` (`0032_tc_catalogue.sql:632-675`, `0004:1053`) :

- `supports_lecture` : tout compte connecté lit tout fichier du seau `supports` dont le premier segment du chemin est l'identifiant d'une `library_resource` existante, sans regarder la version ni les droits d'accès (`access_policy`) : un élève lit un support retiré ou réservé à une autre Classe en devinant son identifiant. La porte prévue existe : `autoriser_lecture_version(p_resource_version_id uuid)` (`20261012100002_c35_support_key_format.sql`) et la fonction Edge `bibliotheque-lecture`.
- `avatar_lecture_foyer` : seau `avatars`, lecture par soi-même ou par son foyer (`profil_de_mon_foyer`). L'enseignant ne voit pas la photo de ses élèves, l'administration non plus : la doc produit (`01`, Espace Groupe) montre les avatars des élèves de la Classe à l'enseignant.
- `photos_enseignants_ecriture` : tout compte connecté écrit dans « son » dossier du seau `photos_enseignants` ; seul un enseignant devrait pouvoir.

## 2. Critère de réussite

C'est fini quand :

1. une migration horodatée remplace `supports_lecture` par une policy qui n'autorise la lecture directe à personne hors administration (`drop policy supports_lecture` ; `create policy supports_lecture_admin for select to authenticated using (bucket_id = 'supports' and coalesce(app_role() = 'admin' and app_account_valid(), false))`), la lecture des élèves et enseignants passant par la fonction Edge `bibliotheque-lecture` (URL signée après `autoriser_lecture_version`), ce que le client fait déjà si `lib/core/bibliotheque/*_supabase.dart` appelle la fonction Edge (vérifier ; sinon section 8) ;
2. `avatar_lecture_foyer` est complétée par une policy `avatar_lecture_classe` : lecture par l'enseignant des membres de ses Classes (`exists (select 1 from groupe_membres gm join groupes g on g.id = gm.groupe_id where gm.student_profile_id::text = foldername[1] and g.teacher_id = auth.uid() and ...)`, noms de colonnes à lire dans `0019`/`0032`) et par l'administration valide ;
3. `photos_enseignants_ecriture` exige `app_role() = 'teacher' and app_account_valid()` en plus du dossier propre ;
4. le scénario `supabase/tests/scenarios_af_l2_09_storage.sql` prouve, sur le stub Storage (`stub_auth.sql` crée `storage.objects` avec RLS) : un élève ne lit pas un objet `supports/<ressource>/...` directement ; un administrateur le lit ; l'enseignant lit `avatars/<élève de sa classe>/...` et pas `avatars/<élève d'une autre classe>/...` ; un tuteur n'écrit pas dans `photos_enseignants/<lui>/...`, un enseignant oui ;
5. la fonction Edge `bibliotheque-lecture` et `supports_ecriture_admin` ne changent pas.

```sql
-- Audit final 16/10/2026, lot L2-09 (P2-3, P3-3, avatars de classe).
begin;

drop policy if exists supports_lecture on storage.objects;
create policy supports_lecture_admin on storage.objects
  for select to authenticated
  using (bucket_id = 'supports' and coalesce(public.app_role() = 'admin' and public.app_account_valid(), false));

create policy avatar_lecture_classe on storage.objects
  for select to authenticated
  using (
    bucket_id = 'avatars'
    and public.app_account_valid()
    and (
      public.app_role() = 'admin'
      or (public.app_role() = 'teacher' and exists (
        select 1 from public.groupe_membres gm
        join public.groupes g on g.id = gm.groupe_id
        where gm.<colonne_eleve>::text = (storage.foldername(name))[1]
          and g.<colonne_enseignant> = auth.uid()
          and gm.<colonne_actif>   -- lire la colonne de retrait (deleted_at is null, actif, ...)
      ))
    )
  );

drop policy if exists photos_enseignants_ecriture on storage.objects;
create policy photos_enseignants_ecriture on storage.objects
  for all to authenticated
  using (
    bucket_id = 'photos_enseignants'
    and coalesce(public.app_role() = 'teacher' and public.app_account_valid(), false)
    and (storage.foldername(name))[1] = auth.uid()::text
  )
  with check (
    bucket_id = 'photos_enseignants'
    and coalesce(public.app_role() = 'teacher' and public.app_account_valid(), false)
    and (storage.foldername(name))[1] = auth.uid()::text
  );

do $postflight$
begin
  if exists (select 1 from pg_policies where schemaname = 'storage' and policyname = 'supports_lecture') then
    raise exception 'L2-09 postflight: supports_lecture encore présente';
  end if;
end $postflight$;

commit;
```
