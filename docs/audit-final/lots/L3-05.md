# L3-05 - Libellés en double : une clé commune pour les formats et les états génériques seulement

Vague 3 (doublons). Dépend de L2-V. Indépendant des autres lots, mais touche `fr.i18n.json` et `ar.i18n.json` : ne pas tourner en même temps qu'un lot qui ajoute des clés (L2-05, L2-07, L4-01, L4-02, L4-05) ; attendre leur fusion ou les faire attendre.

## 1. But et pourquoi (rapport section 5.1 ; K-41 : une clé = un sens)

454 textes français identiques sont portés par 1 113 clés dans `assets/i18n/fr.i18n.json` (9 925 lignes). Exemples : « {date} à {heure} » 7 fois, « {minutes} min » 6, « page {page} sur {total} » 5, « notifications » 8, « bibliothèque » 7, « un motif est requis » 5, « disponible au branchement serveur » 5, « il est possible que la demande ne soit pas parvenue » 7. K-41 interdit la fusion aveugle : deux écrans qui disent le même mot pour deux sens gardent deux clés. Ce lot ne fusionne que les formats (date, durée, pagination) et les états génériques (« disponible au branchement serveur », « il est possible que la demande ne soit pas parvenue ») dont le sens est le même partout par construction.

## 2. Critère de réussite

C'est fini quand :

1. un script `tool/doublons_i18n.dart` (nouveau, lecture seule) liste les valeurs FR identiques portées par plusieurs clés, avec les clés, triées par nombre d'occurrences ; il sert à L3-V et à toute vague future ; il ne modifie rien ;
2. une section `commun.formats` existe avec `dateHeure` (« {date} à {heure} » / AR « {date} في {heure} », vérifier la forme AR déjà utilisée), `minutes` (« {minutes} min » / AR « {minutes} د »), `pageSur` (« page {page} sur {total} » / AR « الصفحة {page} من {total} ») ; et une section `commun.etats` avec `branchementServeur` (« Disponible au branchement serveur. ») et `demandePeutEtrePerdue` (« Il est possible que la demande ne soit pas parvenue. ») avec leurs AR exacts copiés d'une des occurrences actuelles ;
3. les 30 clés environ qui portent ces cinq textes sont remplacées par la clé commune dans le code Dart (`t.commun.formats.dateHeure(...)`), et retirées de `fr.i18n.json` et `ar.i18n.json` ; `dart run slang` ne signale aucune clé orpheline ni manquante ;
4. aucune autre fusion : « notifications », « bibliothèque », « un motif est requis » restent par écran (K-41), listés dans le commit comme « doublons de sens différents, conservés » ;
5. `verifier_revue` : `libelle-sans-source` baisse (clés retirées) et les nouvelles clés communes portent leur source (`K-41`) ; `flutter test` vert (les tests qui cherchaient un texte le trouvent toujours : même texte).

- Un exemple de script d'outil du dépôt pour la forme : `tool/verifier_jetons.dart` lignes 1 à 60.

## 4. Fichiers autorisés et interdits

Autorisés : `tool/doublons_i18n.dart` (nouveau), `assets/i18n/fr.i18n.json`, `assets/i18n/ar.i18n.json`, les fichiers Dart qui lisent les clés fusionnées (changement d'appel seulement), `lib/core/i18n/*.g.dart` (régénérés par `slang`, jamais à la main), tests qui lisent ces clés.

Interdits : toute fusion hors des cinq textes listés, `tool/revue_socle.txt` (L3-07), `.github/**`, `supabase/**`.

## 5. Étapes

1. Écrire `tool/doublons_i18n.dart` : charge `fr.i18n.json`, aplatit les clés (`a.b.c`), groupe par valeur normalisée (trim), affiche `n<TAB>valeur<TAB>clé1,clé2,...` pour `n >= 2`, trié décroissant. `dart run tool/doublons_i18n.dart > /tmp/doublons.tsv`. Attendu : environ 454 lignes.
2. Pour chacun des cinq textes, lister les clés ; pour chaque clé, `grep -rn "t\.<chemin>" lib test` pour trouver les appels.
3. Ajouter `commun.formats.*` et `commun.etats.*` (FR et AR) avec la source dans le commentaire attendu par `verifier_revue`.
4. Remplacer les appels ; retirer les anciennes clés (FR et AR).
5. `dart run slang` ; lire la sortie : aucune clé manquante en AR, aucune orpheline.
6. `dart run build_runner build --delete-conflicting-outputs`, `dart analyze --fatal-infos`, `flutter test`, `dart run tool/verifier_revue.dart`.
7. Pas de capture (mêmes textes à l'écran).

## 6. Vérifications

- Les six commandes vertes ; `verifier_revue` : `libelle-sans-source` strictement inférieur à la mesure d'avant (1 161 ou la valeur après L3-07).
- `dart run tool/doublons_i18n.dart | head -5` : les cinq textes n'apparaissent plus qu'une fois.

## 7. Pièges connus

- Les paramètres slang doivent garder le même nom (`{date}`, `{heure}`) : un appel `t.x.y(date: ..., heure: ...)` devient `t.commun.formats.dateHeure(date: ..., heure: ...)` sans autre changement.
- L'arabe peut avoir des formes différentes pour un même texte FR (deux traductions légitimes) : si deux clés FR identiques ont des AR différents, ce ne sont pas des doublons (K-41) : les laisser et les lister.
- Les pluriels (`one`, `other`) : « {minutes} min » n'en a pas ; ne pas en inventer.
- `slang` régénère `strings_fr.g.dart` et `strings_ar.g.dart` : les commiter.

## 8. Quand s'arrêter et demander

- Un des cinq textes a des traductions AR différentes selon la clé : s'arrêter sur ce texte, le lister, fusionner les quatre autres.
