## 2. Critère de réussite

C'est fini quand les six corrections sont faites, chacune avec un test :

1. (a) test de la démonstration : les prénoms des demandes sont inclus dans les prénoms du foyer de démonstration ;
2. (b) test : `finAcces` est postérieure à aujourd'hui et antérieure à aujourd'hui plus 90 jours ;
3. (c) test widget 390 et 1440 : le bloc d'alerte est le même widget (même `Key`) et un seul `FilledButton` plein sur l'accueil ;
4. (d) test : avec un profil adulte déjà créé, la carte « Moi-même » montre la phrase d'explication et n'est pas un `Radio` désactivé ; FR « Vous avez déjà votre profil. » / AR « لديك ملفك الشخصي بالفعل. » (ou la cause réelle lue dans `_creable`) ;
5. (e) test : avec un port qui rend un travail, la phrase « pas encore relié » n'est pas rendue ; avec `CapaciteIndisponible`, elle l'est ;
6. (f) test de routeur : aucune occurrence de `go(Routes.tuteurParcours)` sans identifiant ; `grep` dans le test ou test de route qui vérifie que les liens de l'accueil mènent à `/tuteur/parcours/<id>` ;
7. `verifier_revue`, `verifier_jetons` inchangés ou en baisse ; `plein-multiple` ne cite plus l'accueil famille.

## 5. Étapes

Une étape par défaut, dans l'ordre du tableau ; un commit par défaut est accepté, une branche pour le lot.

1. (a) Remplacer les prénoms par ceux du foyer de démonstration (lire `mode_demonstration.dart`) ; test.

3. (c) Lire le bloc d'alerte aux deux largeurs ; le remplacer par le composant d'alerte du dépôt, même instance, bouton tonal « Connecter un appareil » ; test « un seul bouton plein ».
