# LA-01 - Retirer la promesse d'enregistrement audio des cours (réponse A-01, option 1)

Lot créé par l'orchestrateur de nuit le 17/10/2026 après la réponse du directeur à A-01 (option 1, 17/10 01:47).

## 1. But et pourquoi
Les textes promettent « chaque cours est enregistré en audio, conservé trente jours ». Aucune captation n'existe. Le directeur a choisi de retirer la promesse et de garder seulement ce qui est vrai : une personne de l'académie peut observer un cours en direct. La révision passe par l'audio préenregistré du programme (décision du 14/10).

## 2. Critère de réussite
1. Aucun libellé de l'application (fr et ar) ne promet un enregistrement des cours : `grep -niE "enregistr" assets/i18n/fr.i18n.json` ne rend plus aucune phrase qui dit qu'un cours est enregistré ; idem en arabe (« تسجيل » au sens de captation du cours).
2. Les phrases deviennent : fr « Une personne de l'académie chargée du contrôle peut observer un cours en direct. L'image et le son ne sont pas enregistrés. » ; ar « يمكن لشخص من الأكاديمية مكلّف بالمراقبة أن يتابع الدرس مباشرةً. لا تُسجَّل الصورة ولا الصوت. » ; chaque clé modifiée garde sa ligne de source dans `tool/libelles_sources.json`, mise à jour avec « réponse A-01 du directeur, 17/10/2026 ».
3. Le bandeau « Cours enregistré » de la salle (s'il existe, grep) n'est plus affiché.
4. Contrats et accords : si leurs textes vivent côté serveur et sont versionnés (grep `versions_contrat`, `duree_enreg`, `contract_versions`, `09_consentements`), le lot n'édite JAMAIS une version déjà signable ; il prépare une nouvelle version selon le mécanisme existant (migration nouvelle horodatée `20261017140100`, scénario qui prouve qu'une nouvelle version existe et que l'ancienne reste intacte pour les signatures passées). Si ce mécanisme n'existe pas ou si l'on ne peut pas créer de version sans décision juridique, s'arrêter et le dire (section 8).
5. Tests verts : test/i18n, les tests qui citent les clés modifiées (grep), et `scenarios_*.sql` si une migration est écrite.

## 3. Ce qu'il faut lire
- `assets/i18n/fr.i18n.json` lignes 920 à 960 (pointEnregistrement, quoi) et leurs pendants arabes.
- `lib/core/dossier/versions_contrat.dart` (en entier) et la migration qui crée les versions de contrats (grep `contract_versions` ou `versions_contrat`).
- `CLAUDE.md` racine, ligne « Le bandeau Cours enregistré ».

## 4. Fichiers autorisés et interdits
Autorisés : `assets/i18n/fr.i18n.json`, `assets/i18n/ar.i18n.json`, `lib/core/i18n/strings*.g.dart` (régénérés), `tool/libelles_sources.json`, l'écran de la salle qui porte le bandeau s'il existe, les tests qui citent les clés, une migration nouvelle `20261017140100_la_01_*.sql` et son scénario si le point 4 l'exige.
Interdits : versions de contrat déjà présentes (les modifier invaliderait des signatures), `.github/`, `lib/core/theme/`, `lib/features/parcours_offres/`, `site-public/`.

## 5. Étapes
1. Recenser par grep toutes les promesses (fr, ar, Dart, SQL). 2. Remplacer les libellés. 3. Retirer le bandeau. 4. Contrats : lire le mécanisme, puis nouvelle version ou arrêt. 5. Vérifications.

## 6. Vérifications
`dart run slang` ; `dart analyze --fatal-infos` ; tests ciblés ; `verifier_jetons` (2) et `verifier_revue` sans augmentation ; rejeu SQL complet si migration.

## 7. Pièges connus
- Une version de contrat signée ne s'édite pas : seule une version nouvelle est possible.
- Les textes arabes portent des isolats U+2068 et U+2069 : copier la ligne brute ; éditer ligne par ligne, jamais par réécriture JSON entière.

## 8. Quand s'arrêter et demander
Si les textes de contrats signables portent la promesse et qu'aucun mécanisme de version nouvelle n'existe : s'arrêter, écrire le cas, faire le reste.
