## 5. Lecture d'attaquant

**Salle par PageShell (L3-07).** Seules les deux préparations (`_PreparationBranchee`, `_PreparationEleveBranchee`) changent ; l'écran de séance n'est pas touché. `PageShell(actionsCoquille: false)` ne pose ni cloche, ni bascule de thème, ni retour de coquille ; aucune lecture de rôle ou de capacité nouvelle ; le jeton vidéo reste délivré par le serveur. Défaut visible E-1 : `PageShell` ajoute par défaut `OfflineBanner`. Sonde hors dépôt (même composition, `horsLigneProvider` à vrai, 390 x 844) : bandeau générique 0 avec `Scaffold`, 1 avec `PageShell`, en standard comme en Interface guidée, au-dessus du message propre de la préparation. Le texte générique (« Ce qui est déjà affiché reste consultable ») est faux pour une séance. P3, fiche `L3-07-reprise.md`.

**Cause dart2js de L2-05R : confirmée.** Deux constructions web release (`--release --source-maps`, configuration fictive plausible) d'une archive de `7ce2e9bf` : A avec les deux fichiers d'avant la reprise (`f3833f2d^`), B tel quel. Playwright en démonstration administrateur, création « lundi, mercredi, samedi », deux passages à 1440 et à 390 : A laisse le formulaire ouvert, sans message, 4 fois sur 4 ; B le ferme et affiche « Offre créée en brouillon », 4 fois sur 4 (`pw/out/A_*_3apres.png`, `B_*_3apres.png`). Le code généré de A, retrouvé par la carte des sources (`nouvelle_offre_page.dart` lignes 93 à 116), le montre : `echec` est rangé dans la boîte `a6.a`, mais le test `if(j!=null)` lit le registre `j`, et le chemin de succès après l'`await` fait `case 7: j=g`, où `g` vaut `n.gJ()` (la référence Riverpod de l'élément, non nulle) ; le chemin de succès est donc lu comme un échec, et `setState` remet `_message` à `a6.a`, c'est-à-dire `null`. C'est une erreur de compilation, pas du code Dart. Les deux autres usages du motif signalés par la reprise (`lib/main.dart:430`, `admin_invitations/invitations_page.dart:90`) sont compilés correctement dans B (lecture du JS : la variable testée est celle que le `catch` renseigne). Le risque reste latent pour toute fonction de même forme ; la garde de source de L2-05R ne couvre que `lib/features/admin_offres`. Observation O-1.

**Exception d'âge (L2-08R).** Sonde avec les claims réels (`sonde_age.sql`) : tuteur qui fournit un motif pour 4 ans, `23514` ; administrateur pour 2 ans, `42501` ; administrateur désactivé pour 4 ans, `42501` ; administrateur pour 7 ans avec motif (scénario), `42501` ; `child_of` étranger, `42501` ; motif blanc, `42501`. L'exception exige administrateur valide, motif non vide, âge de 3 à 5 ans, et garde foyer, `child_of`, compte récent sans session ; elle est journalisée (`age_exception`). Un jeton qui porterait `app_metadata.role = admin` pour un tuteur passerait : c'est le modèle de confiance commun à toutes les fonctions (`app_role()` lit le jeton signé par le serveur, `hook_jeton`), pas un défaut du lot. L'exception n'exige pas `aal2`, comme `creer_groupe` ; les fonctions F79 de contrôle l'exigent (observation O-2).

**Les quatre RPC fermées (L3-06).** `has_function_privilege` sur la base complète : les quatre surcharges retirées (`creer_groupe` à 6, `modifier_groupe` à 5, `affecter_enseignant_classe`, `publier_groupe_depuis_offre`) : faux pour `authenticated`, `anon`, `service_role`, `agent_ro`. Les quatre gardées : vrai pour `authenticated` (`creer_groupe` et `modifier_groupe` longs aussi pour `service_role`). Aucun appelant restant dans `lib/`, `supabase/functions/`, `test/`. Corps comparés (`pg_get_functiondef`) : la version longue est la courte plus un contrôle de fuseau IANA et deux colonnes ; `null` donne `Europe/Paris` à la création et laisse fuseau et couleur inchangés à la modification ; même garde administrateur.
