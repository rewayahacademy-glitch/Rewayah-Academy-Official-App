# F86 - Comparaisons negatives non null-safe dans les gardes (catalogue actif canon-fixes ea1a0da9)

Methode : analyse statique du texte `pg_get_functiondef` des 412 fonctions du schema `public` (Postgres 16.15, stub_auth + 102 migrations rejoues), motifs `<>`, `!=`, `NOT (a = b)`. Resultat : 65 occurrences dans 51 fonctions. `Ligne` = numero de ligne dans le fichier `.sql` de la fonction (`docs/backend/catalogue-canon-fixes/`). Les nullabilites citees viennent de `information_schema.columns` du meme Postgres.

## Synthese

- **Vrai risque si NULL : 2** - `annonces_observation(uuid)` (garde d'acces sautee si `auth.uid()` NULL) et `transmettre_student_concern(uuid,text)` (garde de cible sautee si `p_cible` NULL, integrite).
- **A durcir par prudence : 3** - `creer_classe_depuis_regroupement`, `creer_offre_horaire_text...` (NULL non atteignable aujourd'hui, mais la garde repose sur un invariant lointain).
- **Faux positifs : 60 occurrences** (colonnes NOT NULL, filtres, commentaires, branches qui ne sont pas des refus).
- Aucune garde d'acces dans une fonction `SECURITY DEFINER` appelable par `anon` n'est concernee : les 2 vrais risques ont une ACL `authenticated` seule.
